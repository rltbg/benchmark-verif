# sha256 — hachage cryptographique (CPU pur, mémoire constante)

**Entrée** : `n` octets, `0 <= n <= 2^40`. Le message n'est jamais stocké en entier : l'octet `i` est l'octet numéro `i mod 8`
(petit-boutien, poids faible d'abord) de `mix64(0x5348413235362D42 + i/8)` (`mix64` = splitmix64 de `spec/WORKLOADS.md`).

**Algorithme** : SHA-256 standard (FIPS 180-4) : état de 8 mots u32 (IV standard), blocs de 64 octets, échéancier `W[0..63]`,
64 rondes avec les constantes `K[0..63]`, padding `0x80`, zéros, longueur en bits sur 8 octets big-endian. Les blocs complets sont
construits directement à partir de 8 appels à `mix64` (mots big-endian `bswap32(bas)`, `bswap32(haut)`) ; le reste (`n mod 64` octets + padding,
1 ou 2 blocs) est assemblé dans un tampon de 128 octets.

**Checksum** : `ck = CK_INIT` puis `ck = ckfold(ck, H[i] as u64)` pour `i = 0..7` (mots du condensé, dans l'ordre H0..H7).

**Validation indépendante** : le condensé (avant le checksum) coïncide avec `sha256sum` du fichier d'octets pour
n ∈ {0, 1, 55, 56, 63, 64, 65, 119, 120, 127, 128, 1000, 10^6}.

**Débit** : octets hachés par seconde. **Mémoire** : ~constante (quelques ko) ; `ideal_bytes = 1024` n'est qu'un plancher nominal.

| preset | n |
|---|--:|
| smoke | 10^5 |
| tiny | 10^6 |
| small | 2·10^7 |
| medium | 2·10^8 |
| large | 2·10^9 |
| xlarge | 1,6·10^10 |
| saturate | 4·10^10 |

**Parallélisme** : aucun (un seul thread ; l'argument `threads` est ignoré).
